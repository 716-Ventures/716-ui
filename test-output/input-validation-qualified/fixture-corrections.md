# Fixture corrections

The initial fixture selected field, document and error text together; their shared PRIMARY ownership cleared the document selection. The corrected fixture checks each selected editor in turn. A later `has_focus` assertion failed in headless Weston despite exact root focus remaining the TextView (`window active=false visible=true, root focus=Some("textview")`). The final fixture checks the exact GTK logical focus target, matching the retained-button test; physical input remains unqualified by this gallery. No production feedback code changed during those corrections.

The first alpha.37 CI run (38156262549) failed on Ubuntu GTK 4.14 with `g_value_get_object: G_VALUE_HOLDS_OBJECT` while setting the error relation. GTK 4.14 declares ErrorMessage as a single reference; GTK 4.16+ declares a reference list, matching gtk-rs 0.9. The compatibility helper asks `AccessibleRelation::init_value` for the loaded runtime’s type and supplies a single accessible object on the older runtime. The normal gtk-rs list path remains in use on newer GTK. Both retain the ErrorMessage relation rather than weakening the accessibility contract. The captured fatal-critical is in `gtk414-initial-failure.log`.
